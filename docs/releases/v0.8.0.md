# Agenvyl v0.8.0

This release replaces the isolated snapshot/publication Workspace pipeline with
one transparent Git-backed working tree per room. It also makes Work execution
sequential while restoring parallel Plan responders, moves captured app builds
into a dedicated artifact store, improves active-run instruction history, and
refreshes the Agenvyl UI.

## Highlights

- Agents now work directly in the room's visible Git repository. Agenvyl
  creates checkpoints before and after runs and records exact versions of
  changed project files.
- Work runs in one room are queued and executed one at a time. Plan responders
  can run in parallel when no Work barrier is active or waiting. Different
  rooms can also run concurrently up to the global limit. Per-room Git prepare
  and finalization remain serialized to avoid repository lock collisions.
- Responders to one message keep the same conversation context from before that
  message. Later Work responders also see files left by earlier runs.
- Static app output is captured as an immutable preview bundle in a separate
  `artifacts/` data directory. Current-build selection follows the room Git
  checkpoint; historical builds never read mutable Workspace files.
- New rooms start in Plan, are named automatically from the first substantive
  message or attachment, and remain manually renameable. Existing rooms keep
  their current workflow mode during the upgrade.
- Opening the Web UI base address selects the room with the newest message,
  falling back to the most recently created room.
- Codex **Add instruction** now keeps prior answer segments visible with author,
  timestamp, and instruction status while continuing the same run.
- SVG previews support mouse-wheel zoom and remain constrained to the viewer.
- Workspace source loading is centered consistently while preview content is
  being prepared.
- Interactive app previews support pointer lock after a user gesture.
- Attachment previews retain access to the Workspace file tree.
- The Web UI uses the updated Agenvyl logo, favicon, and sidebar wordmark.

## Upgrade warning

The Workspace migration from `v0.7.0` is an intentional clean break.
Migrations 031 and 032 remove the legacy isolated-worktree, snapshot,
publication, conflict, materialization, cleanup, and warm-slot model. Migration
032 deletes legacy run Workspace results and drops the old snapshot, slot, and
conflict tables.

Migration 033 changes the workflow-mode default for newly created rooms to
Plan. It intentionally leaves every existing room row unchanged.

Messages and live room files remain, but legacy publication/conflict metadata
and snapshot-based app-build history are not converted into the new preview
bundle history. If you need to inspect those records later, keep a complete
pre-upgrade recovery point and run it with the old Agenvyl version.

Before upgrading, stop active work and retain matching copies of:

1. the PostgreSQL dump;
2. the complete Workspace root, including hidden content;
3. the complete Artifact root when upgrading from a build that already created
   preview bundles; and
4. application configuration and secrets needed for recovery.

Rollback requires restoring the old application together with its matching
database, Workspace, and Artifact data. Do not restore only an old database
over Workspace repositories already used by this release.

## Workspace behavior changes

There is no post-run publish or conflict-resolution step. A failed or cancelled
run can leave files in the live room Workspace, because stopping a harness does
not roll back commands that already completed.

Workspace uploads, moves, deletes, and restores are blocked while any run is
active in that room, including Plan. Agenvyl also blocks prepare/finalization
when the room repository contains an unfinished merge, rebase, cherry-pick,
revert, or bisect.

Parallel Plan assumes the harness honors native read-only controls.
Instruction-only Plan cannot prevent concurrent writes to the shared Workspace
or an external project; use Work for tasks that may modify files.

The removed environment settings are:

- `AGENVYL_WORKSPACE_NOOP_MODE`
- `AGENVYL_WORKSPACE_WARM_SLOTS_MODE`
- `AGENVYL_WORKSPACE_STAT_CACHE_MODE`

New artifact settings are:

- `AGENVYL_ARTIFACT_ROOT`
- `AGENVYL_ARTIFACT_MAX_BYTES`, default `262144000`

## Supported harnesses

- Codex CLI
- Claude Code CLI *(experimental)*
- OpenCode
- Antigravity / AGY
- Hermes
- Cursor CLI *(experimental)*

Add instruction remains Codex-only. Plan enforcement and permission boundaries
remain harness-specific; a room Workspace and external project are not
operating-system sandboxes.

## Supported platforms and installation

Portable packages support Windows 10/11 x64, Linux x64/arm64, and macOS on Intel
and Apple silicon. Releases remain unsigned Technical Preview builds for a
trusted single-user computer.

Install the latest stable build with the commands in the
[installation guide](../user-guide/installation.md), or download a platform
archive and verify `SHA256SUMS` from the same GitHub release.

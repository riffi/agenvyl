# Agenvyl v0.9.0

This release keeps conversations connected to their native agent sessions,
extends live steering to OpenCode, and adds an opt-in conversation-routing
experiment. It also tightens Plan-mode MCP confirmation, expands Connector
conformance coverage, and improves the room timeline on desktop and mobile.

## Highlights

- A selected completed Codex or OpenCode response can accept **Add
  instruction**. Agenvyl creates a linked run in the same timeline card and
  resumes the retained native session without replaying the room conversation.
- Active OpenCode runs now support **Add instruction**, matching the existing
  Codex cooperative interrupt flow. Earlier answer segments remain visible,
  and pending instructions are projected consistently in the timeline.
- AGY can continue a selected completed response by resuming its exact native
  conversation ID. Agenvyl now requires AGY CLI `1.1.8` or newer.
- Plan-mode MCP operations require explicit structured confirmation for a
  bounded integration, target, action set, and known side effects. Approval is
  limited to that batch and run and does not switch the room to Work.
- The new vendor-neutral Connector conformance contract records deterministic
  evidence or an explicit transport waiver for every shipped harness and
  stable contract case. Bounded canonical conversation history is shared
  consistently across adapters.
- External room projects are resolved for each execution, so an unavailable
  project fails before the harness starts instead of relying on stale process
  state.
- Agent code blocks have copy controls. The room header is more compact and
  shows the timeline message count, while routing controls and run details
  reflow more cleanly on narrow screens.
- Room WebSocket subscriptions are cleaned up reliably, unchanged static
  outputs no longer create redundant preview builds, and the portable runtime
  image now includes Git for Workspace operations.
- Developers can run the compiled local stack with `npm run serve:all` and
  execute the connector contract directly with `npm run test:conformance`.

## Experimental conversation routing

Conversation routing remains off by default and can be enabled only with
`AGENVYL_EXPERIMENT_CONVERSATION_ROUTING=true`. The experiment adds **Auto**,
**Room context**, and **Agent session** message routes. A follow-up can wait for
an active response and continue the retained session afterwards, or use
**Apply now** when the selected harness supports active intervention. Ambiguous
Auto routing asks for an explicit agent instead of guessing.

The experiment stores delivery state and queued follow-ups in PostgreSQL and
shows the actual route below each message. Attachments still require Room
context. Use the isolated POC preparation scripts when evaluating the feature
against existing data; do not treat the flag as a stable compatibility
contract.

## Upgrade notes

Database migrations 034 and 035 add continuation-chain metadata, delivery
routing fields, and the queued-follow-up ledger. They do not remove or rewrite
existing room, message, run, Workspace, or preview data.

Native continuation is not a pause or rollback. Tool activity, elapsed
timeout, Workspace changes, and external side effects from earlier turns remain
part of the conversation. Agenvyl explicitly releases retained Codex and
OpenCode sessions when their continuation chain is invalidated. AGY manages its
own retained conversation history; Agenvyl can stop referencing it but cannot
delete it from AGY.

## Supported harnesses

- Codex CLI
- Claude Code CLI *(experimental)*
- OpenCode
- Antigravity / AGY `1.1.8` or newer
- Hermes
- Cursor CLI *(experimental)*

Capabilities remain harness-specific. Active intervention is available for
Codex and OpenCode; completed-response continuation is available for Codex,
OpenCode, and AGY. Plan enforcement and permission boundaries are not an
operating-system sandbox.

## Supported platforms and installation

Portable packages support Windows 10/11 x64, Linux x64/arm64, and macOS on
Intel and Apple silicon. Releases remain unsigned Technical Preview builds for
a trusted single-user computer. Core, Connector, PostgreSQL, and the preview
server bind to loopback by default, but connected harnesses and rendered app
previews can retain their own network capabilities.

Install the latest stable build with the commands in the
[installation guide](../user-guide/installation.md), or download a platform
archive and verify `SHA256SUMS` from the same GitHub release.
